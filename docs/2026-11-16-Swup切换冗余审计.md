# Swup 切换与旧动效冗余审计

本轮针对全局 Swup 接管后仍保留的旧加载反馈、整块入场和重复视觉控制做精简。当前工作区构建 **`0.9.51 / 6fa38f7349dd`**，在 **http://localhost:8090** 完成验证。未新增依赖、调整版本范围、改动数据库或发布流程；未暂存、提交、推送或发布。

## 审计与处理

| 发现 | 处理与保留边界 |
| --- | --- |
| full 执行器与 `pjax:send` 都通知启动 NProgress，旧库每次 start 都可能新增 trickle 循环 | 新增单一进度适配器，重复 start／finish 幂等；140ms 内完成不显示全局进度。保留兼容事件和业务清理顺序。 |
| 文档本地进度与全局进度同时存在 | Docsme 内导航使用文档窗口进度线；离开 Docsme 时只使用全局反馈，原富内容暂停／失败恢复逻辑保留。其他 full 导航中，骨架与顶部进度互斥。 |
| NProgress 的 `done()` 异步删除可能删掉下一次进度节点 | 真实库回归复现：第一轮 finish 后主线程阻塞，旧 remove 在第二轮 start 后运行，造成 status 非空而 DOM 消失。适配器关闭库的自动 trickle，独占显示与推进 timer，结束时同步清 timer、重置 status 并 remove，不再调用异步 done。 |
| 全局进度只有颜色和高度，实际为 static，位于桌面菜单栏后 | 补齐固定定位和层级，改为 2px 细线并穿透指针；移除旧 peg 发光装饰。桌面／390px 与 reduced-motion 的真实渲染回归检查定位、层级、单节点和点击穿透。资源预算没有放宽。 |
| 骨架淡出结束后，才发 ready 并播放正文入场 | 导航内容就绪后立即结束骨架，不再把装饰退场作为额外等待。原有提交、初始化、代次复核、ready 和错误恢复顺序保留。 |
| Links 详情的 CSS 展开与新通用 WAAPI 同时控制 opacity／transform | 通用入场不再作用于 Links 详情，保留组件展开／收起的可见性和指针状态，去掉 40ms 延迟。实站默认未展开时 opacity 为 0，且没有通用详情入场。 |
| 朋友圈筛选和分页会把新卡片整批隐藏，再下一帧入场 | 卡片直接插入可见状态，移除 `is-entering`、专用 rAF 和装饰位移。真实列表更新反馈、去重、分页、游标与选中状态保留。 |
| 商品详情外层已有入场，普通／订阅购买区又各自 fade；支付页还有父子 fade | 移除 BuyBox、SubscriptionBuyBox、Payments 和 PaymentOrderItem 的整块 fade／import。商品页面仍由外层处理入场，业务 loading、错误、付款状态和轮询不变。 |
| 动效安装在旧单例检查前，重复初始化会增加监听 | 同一 document 复用一次安装，dispose 只释放自己的登记和监听，避免重复正文与高亮动画。 |
| 图库旧 scene-in、旧详情侧栏动画和早期 group 时长已失效／被覆盖 | 删除三套无效动画及重复时长。完整 CSS AST 对照确认只移除约定项；保留 `contain:paint`、当前共享图片／定向步进、胶片条显隐和取消屏障。 |

没有删除 `window.pjax`、`pjax:*`、草稿投票、历史同步、插件初始化、评论和分享生命周期。Finder 分帧渲染、Reader 目录抽屉、图库图片衔接、窗口最小化／恢复、购物车单项删除等具有明确用途的交互继续保留。

## 范围与选择规则

本轮升级主题三的开发、构建、浏览器运行依赖和测试工具，并刷新允许范围内的传递依赖。保留此前主题适配改动；未升级 Halo / 已安装插件，未部署生产、提交或推送 Git。CI/CD 仅同步本地工作流中的工具版本，没有触发远端运行或发布。

以执行日官方 npm registry 的版本、发布时间和 engines / peer 声明为依据，选择**发布满 7 天的最新稳定版**。这是项目已有的 `minimumReleaseAge: 10080` 要求；本轮没有关闭该规则，也没有新增年龄例外。`latest`、预发布、实际选择和实际验证分别记录，不能将下面的选定版本一概称为官方最新。

官方查询的完整时间和元数据见 直接依赖快照（本机 `output/dependency-upgrade-2026-09-26/registry-direct.json`）、候选选择（本机 `output/dependency-upgrade-2026-09-26/research/eligible-stable.json`）。以下发布日期均为 UTC。

## 实际适配

1. **pnpm 12 配置迁移**：将 `package.json#pnpm` 的 override / patch 迁至 `pnpm-workspace.yaml`；旧 `onlyBuiltDependencies` 改为 `allowBuilds: { esbuild: true }`。保留严格发布时间、来源信任、构建许可和运行前依赖一致性检查；增加严格 peer 检查和包管理器版本不一致报错。依据 [官方迁移说明](https://pnpm.io/migration)。
2. **解决 PostCSS 声明冲突**：原 8.5.23 pin 低于 Vite 8.3.0 要求，删除后锁定 8.5.28。Archiver 8 的 `ZipArchive` API 则仍需 CLI 两行补丁；保留并验证实际应用和打包行为。
3. **锁定构建工具**：`packageManager`、Node engine、workspace 与 CI/CD 版本一致；官方 Halo `theme-cd.yaml@v4` 提供 `pnpm-version` 输入，本地 CD 显式传入。机器默认 Node/pnpm 未切换，验证命令使用明确的本地工具路径。远端 Linux CI/CD 未执行。
4. **Vite 配置和构建标识**：使用 `import.meta.dirname`，消除新版配置加载警告；构建 revision 纳入 `pnpm-lock.yaml`、workspace 配置及补丁，避免仅传递依赖变化却复用旧标识。保留已有入口、拆包、CSS preload 和资源版本化机制，并做实际产物/浏览器验证。
5. **Tailwind 扫描范围**：原自动扫描会读取报告里的示例图标名。本轮用官方 `source(none)` 和显式源码/模板路径限制构建输入，覆盖全部 `src` 与模板。加入额外报告类名后重复构建，91 个资产文件逐字节一致。依据 [官方 source 规则](https://tailwindcss.com/docs/detecting-classes-in-source-files)。
6. **许可与必要测试**：按 Alpine 3.17.3 固定标签重新取 LICENSE，内容 SHA 与原许可一致；Lucide 更新覆盖版本并复核上游许可。重新生成两处第三方声明（38 个分发依赖）。新增 20 条独立 fixture 测试，防止 pnpm 迁移后旧字段被忽略、构建许可扩大、关闭 peer/engine/年龄策略及注释误认。

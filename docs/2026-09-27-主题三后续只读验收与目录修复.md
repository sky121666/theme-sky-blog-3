## 实际缺陷与修复

旧构建中，文章 `/archives/editor-feature-demo` 的“四级标题” `heading.id` 是字面百分号编码串 `%E5%9B%9B%E7%BA%A7%E6%A0%87%E9%A2%98`。目录初始化先解码 URL hash，再与原始 ID 比较，导致带 hash 冷打开时高亮首项。点击目录后完整后退到首页、再前进回文章时，浏览器以 `back_forward` 完整加载文档；内部 `.window-body` 的 `scrollTop` 从 1644 变为 0，而 URL 仍带目标 hash。此时主题没有为内部滚动容器恢复锚点，因此目标标题又回到视口下方约 1750px。这是高亮匹配与内部滚动恢复两个独立现象。

[post-outline.js](../src/apps/reader/runtime/post-outline.js) 现在先按原始 hash 匹配标题 ID；若未命中，则只规范化有效 `%XX` 转义的十六进制字母大小写，再尝试 URI 解码匹配。对于存在的标题锚点，在内部滚动容器尚为顶部时等待目标可见并恢复位置。用户滚动、触摸、滚动按键、hash 变化或组件销毁会取消待执行的恢复，避免迟到滚动覆盖新操作。[回归断言](../scripts/verify-core-page-regressions.mjs) 覆盖大写/小写编码 ID、高亮、内部滚动恢复与用户滚轮取消。

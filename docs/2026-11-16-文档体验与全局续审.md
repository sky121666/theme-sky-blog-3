# 文档体验与全局续审

本轮从 `0.9.51 / 7d6f1db3e0cc` 的未提交工作区接续，保留全局 Swup、桌面、小组件及各应用的既有行为。当前验证构建为 **`0.9.51 / b6a4c9d28efd`**，8090 为 Halo **2.27.3**、Docsme **1.10.2**。没有更新依赖、版本或数据库，没有提交、推送、发布或部署。

目标是修复能够证明的功能问题，并让文档的查找和阅读更直接。没有按重复行数拆分模块，也没有新增导航引擎或装饰动效。使用 Halo Theme、故障诊断、Impeccable 与 Ego Browser 的相关方法；浏览器检查与自动化执行的结果分别保留。

## 全局复核范围与保留项

直接检查了文档、五类 HTML 分页、归档、阅读点赞、共享搜索、导航等待／清理、小组件数据读取及商城查询生命周期。其他模块通过当前源码的完整契约、离线行为和真实页面巡检回归；这不等于逐行证明所有源文件永远无缺陷。

- 保留 `window.pjax`、兼容事件与各插件挂载入口：仍有真实消费者，移除会破坏切换。
- 保留分页各自的 DOM 协议、去重、游标和销毁逻辑：相似代码服务于不同数据形态，不再为减少行数强行抽象。
- 保留业务自己的加载和错误恢复：导航预取不代替分页、图片重试或交易状态读取。
- 构建产物由构建器生成，不手工裁剪或格式化。源码范围的空白检查通过；完整 Git 空白检查仍报告 Svelte 生成文件中的既有字符串空白。

文档预取在三个宽度都实测为：**在途预取＋点击共 1 GET**。服务器给已完成响应设置 `no-cache, no-store`，因此已完成预取后点击仍发新的前台 GET（共 2 次）；这条恢复到前台读取的行为正确，但不能把它说成已经验证「可缓存响应复用」。

归档实页追加检查中，旧断言要求跨应用等待显示整面骨架，与已批准的统一导航方案冲突。修正为「保留当前内容＋轻量进度」，仍检查 `aria-busy`、源内容与结束清理；原始失败日志保留，未恢复已淘汰的遮挡效果。

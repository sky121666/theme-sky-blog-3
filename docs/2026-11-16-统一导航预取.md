# 统一导航预取与等待反馈

本文保留首批 `85538d8289ca` 的实现和验收。逐文件审计后的请求所有权、通知、商城及局部 App 修复，以及最终 `dfcf1b4fc65b` 的结果，见[全局导航审计修复](2026-11-16-全局导航审计修复.md)。

本轮延续 Swup 全局导航，在主题 3 的既有桌面、Dock、窗口、草稿和插件生命周期上统一预取。以实际导航速度、交互连续性和稳定性验收；资源体积不等同于性能。没有新增依赖，没有放宽服务端缓存策略，也没有调整版本、提交、推送或发布。

## 实现边界

- 菜单、Dock、文档与动态插入的托管链接共用注意力监听、在途请求和缓存规则。移除旧 `rel=prefetch` 和提前应用 CSS 的独立路径。
- 使用官方 Swup Preload 的 hover/focus/touch 触发与设备检查；关闭可见链接、初始页面和整站批量预取。Save-Data／2g 不发投机请求，正式点击保持可用。
- 明确目标后，按当前构建清单预热 CSS 和模块。CSS 只下载，模块只下载／解析／编译；不提前应用样式、求值业务模块或挂载应用。正式导航继续等待自己的资源与注册门禁。
- HTML 先覆盖已识别的公开文档、归档、分类、标签、友链、瞬间、图库和默认文章路径。非文档查询仅接受已知只读参数；文档保留已有表示参数，同时排除操作／令牌类参数。未知路由继续正常导航。
- 商品只预热应用资源；账户、购物车、订单、结算、付款及写请求不进入公开 HTML 预取缓存。没有新增媒体原图或第三方 API 的批量预取。
- 投机 HTML 最多 2 个在途，不排猜测队列。点击接管同 URL 在途请求，取消无关投机。最后一个前台消费者取消时中止实际响应体；尚有其他消费者时保留共享请求。
- accepted 时立即为目标在途请求建立当前 intent 的一次性消费权。预取即使在正式读取前刚好完成，也能交给这次已接受导航；结束、被新意图取代或失效时释放。这不是可供未来导航复用的缓存，未点击的 `no-store` 完成结果仍立即丢弃。
- HTML 缓存最多 12 页、最长 20 秒，并进一步受源站 `max-age`、`Age`、`Date` 限制。当前保守实现拒绝 `private/no-cache/no-store/Vary`；这不代表 HTTP 标准禁止浏览器存储所有 private 或 Vary 响应。
- 缓存只接纳 200、同源无重定向、HTML 类型且主题页面协议完整的响应：唯一非空 title、唯一窗口根、app／模式／variant 与清单一致。206、错误、空体、非 HTML、缺失协议与重定向不入缓存。
- 对已知不能保留的 URL，短期只做资源预热，避免反复产生完成后无法复用的 HTML 投机请求；真实点击仍正常读取。账号／写入、评论事件、窗口重新聚焦和历史缓存恢复使相关结果失效。

## 等待与动效

离页守卫接受后，真实点击目标立即显示轻微反馈及 `aria-busy`。成功、失败、取消、被新导航取代和原生交接都恢复原属性；旧 cleanup 不得清掉新意图的反馈。

HTML 导航等待期间继续显示原内容，不再用整面骨架遮住窗口。Docsme 内仍由文档细进度负责，其他导航沿用延迟显示的全局细进度。业务组件自己的 loading 不受影响。正文入场、图库 View Transition、侧栏选中和窗口恢复继续由原 owner 管理，不添加请求前退场或等待动画结束的门禁。

## 性能与验证口径

优化前的 8090 浏览器抽样中，导航发起到主题 ready 约 572–1185ms，主要等待在完整 HTML 响应到达之前。匿名请求和当前浏览器会话的缓存头不同，不能用匿名的 3 秒新鲜期覆盖浏览器的 `no-store`，也不能将响应接收时间全部归因为后端计算。

预取命中可以提前完成网络工作，但首次未知目标、不可缓存的 HTML、必要 DOM 提交和实时交易数据仍需等待。主题 ready、首屏绘制与全部插件可用是不同指标；不以一个 ready 数字声明所有组件都已加载，也不承诺统一的提速百分比。

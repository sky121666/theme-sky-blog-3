# 窗口切换、媒体选图与访客版本验收

Halo 仍然直接输出可阅读的 HTML。站内点击由 Swup 与现有窗口管理器接管，保留桌面、Dock、草稿和历史；图片下载不决定是否允许切换窗口。局部动效继续使用已有实现，不引入新的全站路由器或动画库。以下是 8090 开发站的可复验场景，不是公网或真机速度承诺。

| 入口 | 手动验证 |
| --- | --- |
| [图库](http://localhost:8090/photos) | 滚动列表、点缩略图，再用方向键或胶片快速切换。按信息按钮、缩放或返回时，不需要等原图。较慢图片先用已下载的小图衔接；失败时在图片区域重试。 |
| [有静态封面的照片](http://localhost:8090/photos/photo-xqgifxkz) | 列表与胶片仅用静态封面。直接打开此详情可看原动画。开发样本保留原始附件，仅调整两条照片的封面；不是在主题里按扩展名猜测动画。 |
| [商城商品](http://localhost:8090/shop/products?view=all) | 在独立冷会话试中卡、大卡和小列表；用浏览器的 `currentSrc` 和 Network 检查实际候选。已下载的大图在缩小后可能被复用，不能当作冷会话结果。 |
| [文档章节](http://localhost:8090/docs/halo-theme-sky-blog-1/jianjie) · [文章](http://localhost:8090/archives/mac-restart-podman-container-start) | 直接打开先读正文，滚动后点其他窗口，浏览器后退恢复阅读位置；写评论后尝试离开，验证取消后草稿仍在。 |

**访客版本。** `pnpm run verify:8090:delivery` 先重载后检查；只复验普通访客用 `pnpm run verify:visitor-build`，不会改站点。分别读取两个独立匿名浏览器会话的原始响应（默认缓存与请求头 `Cache-Control: no-cache`），识别 `#shell-core-style` 的版本、阅读窗口标记和开机脚本，再检查运行时加载的 JS。远端 manifest、运行时版本正确不能证明服务器返回了新模板。验收失败时记录两个结果；仅在确认为 Halo 页面静态缓存、且本实例允许刷新时，使用插件的正式清理入口。没有在用户访问或 Swup 切换时清缓存。本地之外用 `SMOKE_BASE_URL`、`READING_CHAPTER_PATH`、`READING_ARTICLE_PATH` 指定存在的样本；此验收配置要求已安装 Docsme、图库和商城。

**图片与动效。** 保留真实链接和原始图片 URL。禁用共享元素动画、开启减少动态效果、点击另一张或遇到下载失败，都应能独立提交导航。商品切大图时同步更新主图的 `src`、`srcset`、`sizes`，没有候选就清除旧候选。UI 的尺寸标记不能生成新的图片文件；像素尺寸与实际传输字节各验一次。

**插件边界。** 现场使用[评论组件 3.5.1](https://www.halo.run/store/apps/app-YXyaD)和 [AI 助手 3.1.0](https://www.halo.run/store/apps/app-riNgb)。主题沿用评论区按需呈现、草稿保护与插件的官方注册方式；本次没有使用请求拦截在访客浏览器里推迟插件脚本，也没有改变站点设置。支付、订单和登录不会因本轮阅读优化增加意图预取。

## 为什么撤回阅读页的提前下载

对文档章节、文章各测 20 对冷访问；每对轮换对照组与实验组的先后顺序。80 ms 延迟、10 Mbit/s 下行、CPU 4 倍降速；关闭浏览器缓存，源站返回未缓存的 HTML。两个组唯一的交付差别是一条带实际构建版本的 Swup 导航 `modulepreload`；每次均核对只有一次实际模块下载。表中“就绪”指主题接管导航，“标题”指读者首次能看见阅读标题。时间单位毫秒。

| 入口 | 就绪中位数：无 → 有提示 | 标题可见 P75：无 → 有提示 | 决定 |
| --- | ---: | ---: | --- |
| 文档章节 | 2101 → 2034 | 721 → 796 | 标题晚约 75 ms，撤回 |
| 文章 | 2375 → 2098 | 710 → 792 | 标题晚约 82 ms，撤回 |

两组都超过预先设定的标题退化上限（50 ms），即使导航就绪更早，也不能算阅读体验通过。正式模板不输出这个提示。已有桌面公开链接的意图预取继续工作。原始对照记录为 `output/window-delivery-20261117/preload/cddf8afa6f36/run-bcLwdA/report.json`；以后可用 `node scripts/measure-reading-preload-ab.mjs` 在本地测试代理中复现实验，无须给访客临时开启此功能。

## 图片实际下载

8090 的 `photo-xqgifxkz` 和 `photo-yvqae9y4` 原先把同一个 9,186,808 B、96 帧、1920×1080 WebP 同时作为封面和原件。现在共用一份 800×450、40,444 B 的单帧附件，只更改 `spec.cover`。两次独立冷访问列表均只取一次静态封面；两次从相邻照片进入、仅显示缩略带也没有请求这份动图；明确打开目标详情后原件各成功下载一次。并非所有 WebP 都是动画，其他照片未改。写入前后快照、两个记录各自的回退条件及网络字节在 `output/window-delivery-20261117/animated-cover/`。

在同一 279.33 CSS px 商品卡上，DPR 1 选择 400 px PNG，响应体 229,483 B；DPR 2 选择 800 px，913,471 B。两者 HTTP 均为 200 且解码成功。52 px 小列表在 DPR 2 只取一张 400 px 候选（本实例可用的最小尺寸）。多图商品切图、失效候选和重试另用隔离数据验证；不能把这些记为对单图实物商品的真页多图验收。复验：`node scripts/verify-commerce-media-selection.mjs --live`。

文章页头的主题封面明确声明 `eager/high`；正文照常由服务器输出，读正文不依赖封面加载。经 Swup 打开文章时，在目标正文接入窗口前，保留第一张普通图片、显式优先级、链接、图库及自定义组件的图片，仅给其余未声明策略的普通图片使用原生 `loading="lazy"`。8090 的 [编辑器功能演示](http://localhost:8090/archives/editor-feature-demo) 有 6 张正文图；从归档点进时，只改变最后一张普通图，滚近之前零请求，滚近后成功解码。普通直达的 6 张仍是编辑器原始标记，并未因此变成服务端懒加载；全站统一更改历史正文须由输出标记的编辑器或 [Halo 服务端内容处理器](https://docs.halo.run/developer-guide/plugin/extension-points/server/post-content)负责。

图库通过 `node scripts/verify-photos-switch-live.mjs` 测量关掉意图预取后每次真正的目标 HTML 响应；不以内部“内容就绪”回调替代最后一个字节。在最终开发构建 `c971b65d5b62`，20 次详情切换的 `responseEnd` → 内容交换 P75 为 22.7 ms，而导航开始 → 内容交换 P75 为 311.5 ms。单独扣住原图 2,053.6 ms 时，预览仍能缩放到 220%、水平拖动 35 px、垂直拖动 40 px，再后退回上一张。重试所用的真实 3072×4096 原图解码后保留预览倍率，中心位置偏差小于 0.001 px。浏览器窗口尺寸与原图像素各自独立；这里没有测量真机 120 Hz 帧率。

## 最终回归

8090 的 Halo 2.27.3，主题 `0.9.51 / c971b65d5b62`。7 个公开入口普通访问与绕过缓存都收到了匹配的原始 HTML 和壳层脚本；`pnpm run check`、13 个重载检查点、40 个桌面／手机导航场景全部通过。Chromium 和 WebKit 各通过 11 项阅读、13 项开窗检查。工具栏拖动按浏览器帧采样，没有据此推断真机刷新率。

快速后退再前进时，官方评论表单可能尚未重新挂载。导航现在用已见过的草稿标识与版本识别同一份已保存草稿，表单稍后挂载不会让已确认的前进静默失效。两种引擎的桌面、触屏共 4 个组合均验证：确认一次完成前进，取消后回读草稿，在目标响应返回前输入新文字会阻止离开。未发送评论。商城规格、购物车与支付失败恢复通过当前编译资源的隔离交易测试；没有创建真实订单或付款。

全站浏览器 smoke 的 24 项里，17 项仍因同一外站 favicon 的 `ERR_BLOCKED_BY_ORB` 被记为失败，6 项为 200、1 项预期为 404。报告没有页面脚本错误、控制台错误或站内响应错误；保留该非零退出。汇总及原始报告在本地 `output/window-delivery-20261117/`（`acceptance.json`、`smoke-history.json`、`public-history/public-delivery.json`）；普通页面缓存只在本地通过插件刷新，未改变日常访客缓存策略。

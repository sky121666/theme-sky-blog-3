# Dock 图标与文字对齐修复

日期：2026-11-17。环境：本地 8090，主题 `0.9.51 / fffe71702b65`。本轮只处理 Dock 配置与文字回退布局，没有提交、推送或发布。

## 图标

按用户要求，将 Dock 菜单的四个自定义项改为项目现有 Lucide 图标库的 SVG：

| 菜单 | 图标 | 地址 |
| --- | --- | --- |
| 首页 | `house` | `/` |
| 朋友圈 | `users-round` | `/links` |
| 瞬间 | `camera` | `/moments` |
| 文章 | `file-text` | `/categories` |

修改仅包含各项的 `icon_type`、`icon`、`image_url`。菜单名称、链接、顺序、背景色和其他注解保持原值。商店与系统设置继续使用已有默认图标。

原首页、文章使用不被模板接受的 Base64 图片地址，因此显示首字回退；朋友圈也保存了一份未使用的 Base64 图片。现在清空这四项的图片字段，不再让菜单读取携带约 1.32 MB 的内嵌数据。

原始记录、修改后记录和恢复补丁保存到仓库外私有目录 `halo-ssr-menu-repair-20261117/dock-standard-icons/`。写入前检查版本和菜单身份，PATCH 在服务端检查完整旧注解，写入后逐项回读，确认其他字段不变。没有上传或删除附件。

## 文字为什么偏

`.dock-icon-svg > span` 把首字元素撑到图标内部区域的完整宽高，但 `.dock-icon-initial` 没有自己的内容对齐。外层 Flex 只居中了这个矩形，矩形里的字仍从左上角开始排版。

真实浏览器中，“首”“文”在静止时文字框中心向左偏约 2.20 px、向上偏约 2.59 px；“文”悬停放大后偏差扩大到约 7 px。不是旋转，也不是 Swup 重复加载。

在 `.dock-icon-initial` 上补齐 Flex 水平与垂直居中。没有改变整个图标的位置或加入补偿位移。修复后静止和放大状态的文字框水平偏差均为 0，垂直偏差约 -0.39 px，处于字体行框的亚像素误差范围。

## 加载测量

相同 8090 实例、Node 24.21.0，每条接口和页面前后各请求六次，使用 `Cache-Control: no-cache`、identity 编码，均未命中 Halo 页面缓存。下表为完整响应耗时的中位数。

| 对象 | 修改前 | 修改后 |
| --- | ---: | ---: |
| Dock 菜单 API | 148.27 ms | 12.54 ms |
| 首页 `/` | 292.78 ms | 200.62 ms |
| 朋友圈 `/links` | 281.75 ms | 148.94 ms |
| 文档项目 `/docs/halo-theme-sky-blog-1` | 289.88 ms | 157.30 ms |

菜单响应由 **1,330,724 字节降至 7,455 字节**。这些是顺序执行的前后测量，不是交错 A/B，也不是页面可交互耗时；不能将该结果推广为所有页面的固定提速比例。

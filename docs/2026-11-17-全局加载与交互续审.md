# 8090 全局加载与交互续审（2026-11-17）

本轮分别测三件事：匿名访客直达时何时能看见和操作窗口，桌面内切换时浏览器做了多少工作，以及用户连续操作或请求失败后能否完成任务。一个入口返回 200 不等于这三项都通过。版本号沿用 0.9.51，不是正式发布说明。

## 桌面内切换

在文档项目、文章、图片、标签、追番状态，以及从 Dock 切到友链、从友链返回桌面的七条路径上，用普通浏览器点击并记录完整目标 HTML 实际经过多少次 `DOMParser.parseFromString`。修前每次为 7–8 次。主题现在把同一份已经校验的目标文档传给 SEO、代码高亮、表单和图库插件适配；图库依次加载资源时只保留 URL。Swup 的目标文档和预取的公开性校验各有职责，予以保留。计数未包含浏览器内部解析片段或创建节点的成本，不能按减少的解析次数换算提速倍数。

最终构建每次只解析 **2–3 次**。Chromium 七条路径各 3 次（21/21），WebKit 各 1 次（7/7），均维持桌面节点、正确落点及页面就绪。Chromium 的一次修前／修后对照中，完整解析本身的累计耗时中位数从 **10.7 ms 降为 4.3 ms**。初次并行验证有文档、分类、友链的起页等待超时，保留了原始记录；同一操作后续通过，未据此认定超时根因。

最后再用同一构建单独测 21 次正常点击（开启节省流量模式以关闭意图预取；无故障注入）。每次恰好 1 个目标 HTML GET，中位数从受理起 **2 ms 发出、54 ms 收到首字节、372 ms 收完 HTML、400 ms 窗口就绪**。逐次计算的“收完至就绪”中位数为 30 ms。七条路径中，追番状态切换的就绪中位数为 626 ms；目标 HTML 在 615 ms 收完。这些是分组中位数，不可直接相减当作逐次统计。

单独向 8090 请求相同的七个落点各三次，明确要求 HTML、gzip 和绕过页面缓存，不经过浏览器或 Swup。正文首字节中位数 45 ms，完整响应 331 ms，压缩后正文中位数 35,717 B。因此要进一步优化冷切换，优先分段测量 Halo 渲染完整响应的过程。现有证据不能把等待精确归因给某个插件、模板或数据库查询。主题继续保留可直接访问的完整 HTML 和插件数据。

## 页面操作

| 通知中心 | 面板未打开时不挂载小组件。首页和友链直开，隐藏卡片从 12 张降到 0 张，小组件相关 JS 从 16 次请求降至 9 次（这 9 次包含桌面本身需要的部分）。打开后仍有 12 张，关闭再打开不再增加请求。约 1.9 秒的关闭／展开／再次关闭观测，增强扫描从 58／39／57 次变成 0／1／0 次；那一次有数据更新。 |

| 朋友圈 | 切来源先清理上个来源的卡片与分页状态；同来源刷新失败仍保留原内容。桌面、手机各延迟一次来源请求，等待期旧动态由 20 条变成 0 条，响应后出现正确空态，回到全部动态恢复 20 条。 |
| 装备 | 平滑滚动途中再次点「下一件」，从上一次选定的目标继续计数。两端从第一件连点两次由停在 2/3 改为 3/3；手动滚动可以接管。 |
| 代码高亮 | 新页成功接管时撤销旧页尚未执行的重放。8090 点击友链 → 瞬间，停留并放行真实 Shiki 1.5.2 模块，当前页正常高亮；先返回友链再放行，旧配置写入由 1 次变为 0 次。失败或取消导航时保留原页的待执行任务。 |

## 仍然能感觉到的等待

- 瞬间首屏封面是站点选择的 1920×1080 动画 WebP。首次 15 个入口的盘点中，三次均观测到这张图传输了约 9.19 MB。它在桌面与手机的首屏内；列表更下方也引用了它，但在浏览器对照中只换掉封面，列表没有在首屏请求该图。Halo 输出的四档候选和对应缩略图接口都回到了同一原文件。单独暂扣图片约 1.9 秒，两端均能先操作通知中心。要降低首屏字节数，可以单独给「瞬间 → 封面背景」选择优化后的素材，正文仍可看原图；改成懒加载不会把现有动画变小。本轮未改附件或配置。
- 通知中心首次展开后，数据型小组件需要等待各自的读取。在友链的一次观测中，渲染器注册后，首个内容链接到约 1.27 秒才可用；重复展开不再重新下载同一批脚本。不能把面板已出现当成异步内容已齐全。
- 装备第 3 件的前景和背景用的是同一份大动画。两端首屏均看不到它，浏览器仍在原生懒加载范围内发送了一个低优先级请求；只有一次传输。暂扣图片时仍可从 1/3 连点到 3/3。若流量是重点，可为这件装备配置更轻的封面；本轮未给所有装备强制加上点击才下载的限制。
- 外站豆瓣海报在本地浏览器实测有加载失败，主题可以确保占位稳定，不能保证图源成功。图片加载中的验证另行放行一张有效图片，验证真实窗口会将占位替换成图片。

## 怎样复测

8090 实际运行 Halo 2.27.3，最终主题为 `0.9.51 / 4e6dc1f3fed0`。完整构建检查、13 个重载检查点、桌面与手机 40 个导航场景通过。15 个公开入口各无缓存直开三次，45 次均看见窗口且能操作桌面导航；各入口就绪中位数落在 400–696 ms，不代表全部图片就绪。全站浏览器 smoke 24 项中 11 项因同一外站图标被浏览器拦截而非零；没有记录到页面脚本异常、控制台错误或站内响应错误。没有把此次公开入口核验计作会员设置、真实付款或移动真机的验收。

普通访客与绕过页面缓存通过两个独立浏览器上下文核对。刷新前，16 个普通入口均读到旧 HTML，对应的 16 个绕过缓存入口均收到当前构建。获授权刷新本地 8090 的页面缓存后，**两种访问均为 16/16**，原始 HTML 与实际加载的壳层资源都是 `4e6dc1f3fed0`。没有改变缓存配置。修前、修后及汇总见本轮证据目录的 `public-current/`、`public-delivered/` 和 `acceptance.json`；导航分段耗时为 `navigation-timing/` 与 `navigation-origin.json`，直开采样为 `cold-current/`。

本地证据根目录为 `output/interaction-review-20261117/`，不进入主题包。全页解析探针会真实点击，仅允许同源只读请求，并保留桌面节点身份、页面类型、规范链接及页面脚本异常。冷启动探针每次新建 Chromium 会话，禁用浏览器缓存和 Service Worker，HTML 带 `Cache-Control: no-cache`；`public-apps` 场景跳过已经播放的开机动画并隔离外站，以测出主题与同源插件的成本。「可操作」指窗口可命中且桌面导航就绪，图片全部解码、数据全部到达是另一项指标。每个入口三次为本机样本，不作用户群体的百分位结论。

COLD_MODE=public-apps COLD_REPEATS=3 SMOKE_BASE_URL=http://localhost:8090 node scripts/measure-reading-cold.mjs

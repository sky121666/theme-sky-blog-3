# 主题导航契约 v1

源码标识：`@theme-navigation-contract v1`。这是主题导航实现约定，不代表某个 Halo / 插件版本已通过运行验收。插件支持范围和组合证据仍以《插件适配契约》《插件适配状态》为准。

## 职责与入口

| 模块 | 职责 |
| --- | --- |
| `src/shared/navigation-link-policy.js` | 根据当前链接和事件快照判断是否接管，无 DOM 查询和导航状态 |
| `src/shell/desktop-shell/runtime/desktop/pjax/click-controller.js` | 唯一 document 冒泡 click 入口；组件事件先运行；提供幂等 install/dispose |
| `src/shell/desktop-shell/runtime/desktop/pjax/navigation-admission.js` | 同步离页投票、一次性许可、提交前复核、原生交接许可 |
| 同目录 `index.js` | 统一 full、same-variant、local 执行器的准入、请求代次和历史所有权 |
| `runtime/shared/page-app.js` 与应用 lifecycle | 活跃应用可提供同步 `prepareLocalNavigation`；只有应用明确支持的视图才复用实例 |

页面只需输出 `a.pjax-link[href]`；可用 `data-pjax-app` 帮助资源推断。动态插入、缓存恢复和 Alpine 更新无需逐链接绑定。`data-pjax-attached` / `data-pjax-state` / `data-pjax-managed` 不再决定是否接管。

`window.pjax.attachLink(anchor)` 仅为旧调用方添加 `pjax-link`，不绑定 click/keyup。主题不提供 `attachLinks`。`loadUrl(url, options)` 是程序导航入口，默认 full；其 Promise 只表示启动或否决，不表示目标页面已就绪。

## 浏览器行为

以下交给浏览器：组件已取消的事件、非左键、修饰键、非 opt-in 链接、运行时未启动、空 href、download、非当前窗口 target（含继承的 base target）、外站 / 非 HTTP(S) 链接、同路径及查询参数的显式 hash（含空 `#`）。显式空 target 覆盖 base target。

Enter 使用浏览器产生的 click。组件 `preventDefault` / `stopPropagation` 和编辑态阻断先于导航。接管后同步阻止默认行为；离页否决不会再退回原生跳转。

## 草稿、请求和历史

1. 捕获桌面布局和主题设置的版本、保存状态、可见 / 编辑状态。所有守卫只投票。
2. 全部同意后才发送 `theme:navigation-accepted`，取得既有 intent 并开始请求；否决不抢占上一导航。
3. 有效响应及必要资源就绪后，在持久桌面协议、标题栏、插件 UI 和正文发生改变前统一复核。等待期间修改、开始保存或守卫集合变化均撤回许可，保留草稿。
4. 清理同步执行且每个许可最多一次。same→full 回退复用许可和 intent，不重复确认 / accepted / history。
5. full 响应必须恰好包含一个 title 和一个窗口根节点。缺失或重复时通过许可交给浏览器；不能先清理再发现结构异常。
6. 旧响应不能替换 DOM、结束新 loading 或发 ready。请求失败在提交前保留原内容；提交后失败进入受控恢复，不声称旧状态完整保留。

主题 popstate 准入监听必须在 Pjax 构造前注册。已知 history index 的否决使用真实差值返回源项；未知 state 不猜步数，使用 replaceState 恢复源 URL 和主题状态，无法保证保留未知历史栈形状。

尚未写入目标项的原生跳转使用 assign；已有目标项或 popstate 使用 replace。原生交接不提前丢弃草稿。两个主题 beforeunload 守卫共享一次许可；新输入、新 intent、pageshow、状态变化或 1500ms 到期使许可失效，第三方 beforeunload 仍可阻止跳转。

## 主题事件

均在 document 派发，`bubbles: true`、不可取消。外部否决继续通过 window 上可取消的 `theme:before-pjax-navigation`（`detail.url`）同步表达。

| 事件 | detail | 含义 |
| --- | --- | --- |
| `theme:navigation-accepted` | intentId, url, source | 一次获准导航；source 为 click / programmatic / popstate |
| `theme:pjax-ready` | intentId, url, appId, root, mode | 当前主题 DOM、必要资源、同步组件初始化、历史和 loading 已收尾；mode 为 full / same / local |
| `theme:navigation-settled` | intentId, url, outcome, reason | 每个 accepted 的唯一终态；ready / cancelled / superseded / failed / native |

ready 先于 settled(ready)。失败、撤回和被抢占的导航没有 ready。native 仅表示开始浏览器交接，不表示目标已加载。ready 不承诺评论、图片、插件业务请求都已完成。

保留库 `pjax:*`、同变体事件和 `theme:content-swapped`，供已有外部消费者使用。主题通用 UI 使用主题事件；Links 的 URL 规范化保留单一 `pjax:same-variant-complete` 同步回调，使规范化发生在 history 提交之后、ready 之前。它不作为页面就绪通知，也不重复订阅 ready。

## 应用内视图切换

`local` 不替换 HTML、不重新 hydrate / dispose 应用或插件实例，不触发 `pjax:same-variant-*` / `theme:content-swapped`。仍经过唯一点击入口、离页守卫及一次性许可，结束被抢占的 HTML 请求，提交 URL / 标题 / 组件状态；Alpine 更新完成后发出 ready 和唯一 settled。桌面小组件重绘和 LightGallery 挂载订阅跳过 `mode=local`；导航菜单等轻量同步仍保留。

当前仅 Links 启用：来源和目标都必须为同源、无 hash 的 `/links` 或 `/links?view=friends`，且活跃应用和组件仍连接 DOM。Header 与侧栏共用 `showPrimaryView`。重复点击当前视图不增加历史；已知 history 的前进后退直接还原视图；离页否决保留原 URL / 视图。跨应用、复杂 query、详情、申请表、未就绪组件保持原 PJAX 路径，程序 `loadUrl` 仍默认 full。

`prepareLocalNavigation` 只返回计划，不改变状态；同步提交前再次检查活跃实例。应用提交后的元数据 getter 异常使用当前 DOM 标题作为缓存回退，避免仅回滚 URL、留下已切换视图。以后新增可复用应用必须分别验证状态、历史、并发和数据请求，不能仅根据 pathname 自动接管。

## 同变体 HTML 的局部刷新

Moments 标签点击使用 `same` HTML 导航：来源与目标均须同源、无 hash，路径为 `/moments`，查询参数为空或仅有单个 `tag`。`pjax/moments-feed.js` 只提供 loading 范围和局部替换计划，请求、离页许可、取消、失败恢复及历史仍由既有协调器负责。

`data-moments-feed-region` 是列表骨架与 busy 状态的边界，`data-moments-feed-content` 包含列表、分页和空态。目标响应具有有效 feed 内容且标签区域结构匹配时，仅替换该内容与标签子节点，保留封面、头像、标题栏、应用根节点及标签容器。提交前销毁旧分页并清理旧列表交互，随后初始化目标列表；分页初始化从 `data-pjax-target-url` 获取尚未提交到 history 的目标路径。

快切只有最后一个 intent 可以提交；返回当前 URL 使用 `replaceState`，不增加重复历史。请求失败清除局部 loading 并保留原视图，允许重试。该路径仍发送 HTML 请求并遵循 `same` 事件，不属于 `local`；复杂 query、详情、目标结构不符、浏览器前进后退及程序 `loadUrl` 继续使用原页面导航流程。

## 验证与恢复

- 离线：`pnpm run verify:pjax-navigation`、`pnpm run check`。
- 运行验证命令：`pnpm run verify:reload`、`pnpm run verify:navigation:live`、`pnpm run verify:navigation:pages`、`pnpm run verify:pjax-cold-assets`、`SMOKE_BASE_URL=http://localhost:8090 pnpm run verify:pjax-lifecycle`、`SMOKE_BASE_URL=http://localhost:8090 pnpm run smoke:playwright`。当前构建实际执行范围见[项目进度：当前状态](项目进度.md#当前状态)。
- Links 局部切换：`pnpm run verify:links:navigation`，验证真实 Header 点击、侧栏、同 URL、历史前进后退、否决及旧请求抢占；原始报告只保存在本地 `docs/evidence/`。
- Moments 列表刷新：`pnpm run verify:moments:feed`，验证桌面 / 手机实际标签点击、局部骨架、DOM 保留、目标内容、快切与网络中断后重试；空列表仅使用真实标签样本，缺样本单列跳过。报告保留本地。
- 浏览器验证使用完整刷新，避免旧库匿名监听残留。报告必须记录实际 Halo / 插件、源码和构建指纹；原始报告留本地。
- 恢复顺序：先恢复 ready 发射及对应消费者，再整体恢复点击入口及消费者，最后恢复守卫及执行器提交挂点；同步重建资源。保留用户其他改动，不整仓 reset，也不启用两套点击路由。

## 响应身份与壳层交接（2026-09-30）

`src/shared/navigation-response.js` 将 `appId=auth`、`data-page-mode=auth` 或认证路径识别为认证响应。`pjax/index.js` 在响应解析后交给浏览器完整导航；认证文档不在当前桌面 Shell 中 hydrate。同变体请求也必须按实际响应重新判断身份，不能仅按点击前推断的 App 决定接管。

完整 PJAX 的 HTML 与目标 App CSS/JS 并行准备，解析实际响应 App 后确保注册器、样式和当前导航代次仍有效，检查唯一的 `title` 与 `#window-frame-root`，再提交 DOM。桌面 surface 在替换范围外，首页响应的桌面小组件协议需先同步。资源加载失败、身份漂移、容器不符或认证响应须走完整导航或已定义的失败路径；调用方不能仅根据 `loadUrl()` Promise 推断页面 ready。

以上为源码契约。`verify:pjax-navigation` 是离线检查；`verify:navigation:live`、`verify:navigation:pages`、`verify:pjax-cold-assets`、`verify:reload` 和 Playwright 访问真实站点，需记录同一构建、Halo、登录态与插件组合。前一构建的全站通过不证明当前构建通过。

# 2026-09-28 登录片段加密修复与验证

## 版本与范围

本次本地构建为主题 `0.9.46/1fd18f4f082f`。运行环境是 Halo Pro `2.26.1`；本机插件清单有 46 项，其中 24 项主题契约插件通过严格版本及启动状态核对，`auth-passkey` 为 `1.0.4`。主题最低 Halo 声明仍为 `>=2.26.0`，本次运行验证只覆盖 Halo `2.26.1` 与当前安装组合。

先前构建 `584f65afd686` 的巡检、Docsme 专项和启动稳定性结果保留在[历史验收](2026-09-28-主题启动稳定性修复.md)。本构建另行完成 46 页双端只读巡检；两次报告不混用。

## 修改

- 本地账号登录在 Halo 提供公钥时，只让隐藏字段以 `name=password` 参与提交；可见密码框继续用于输入和自动填充。没有公钥时保留 Halo 原生密码字段名。
- 在文档捕获阶段先于验证码的表单监听器加密。加密库缺失、公钥无效、加密失败或密码的 UTF-8 长度超过 RSA 密钥容量时，阻止提交、清空密文字段并显示错误；用户名或密码变动、返回用户名步骤时清除旧密文及错误。锁屏身份步骤的首次提交仍只切换到密码步骤。
- 新增隔离浏览器契约测试，并纳入 `pnpm run check`。Passkey 插件表单仍由插件自身处理。

## 本构建验证

在 Node `24.21.0`、pnpm `12.5.1` 下，`pnpm run check`、`pnpm run verify:reload`、24 场景 `smoke:playwright` 均通过；重载后首页与 12 个关键页面返回 200，smoke 失败和跳过均为 0。登录和 Passkey 的桌面/移动只读页面共 4 项通过，页面运行时错误为 0。

隔离测试覆盖加密成功、失败返回、抛错、库缺失、无效公钥、超长 UTF-8 密码、字段修改和返回用户名步骤后清空旧密文及错误、锁屏身份步骤，以及验证码先拦截表单事件的情况。真实本地登录页的模拟 `submit` 也确认：成功时提交字段为密文；故障注入时提交被阻止、字段为空并出现错误。这一阶段的登录 POST 均被浏览器拦截。

后续对同一构建完成 23 个路由 × 桌面/移动双视口的只读巡检：46/46 HTTP 200，页面断言失败 0，`DOMContentLoaded` 待完成 0，截图 46 张，前后源码指纹一致。报告为 `passed-with-warnings`：豆瓣外部海报有 16 次浏览器拦截，独立页未播放音视频有 4 次预加载取消；无未解释的主题页面错误。2 次浏览量 Counter POST 由浏览器在本地模拟响应，未送达站点。原始报告仅存本机 `output/interface-audit-2026-09-28-final-1fd18f4f082f/`。

经用户授权，专用本地测试账号完成一次真实登录：页面最终跳转 `/uc/profile`，刷新后仍保持登录态，同一浏览器的当前用户接口返回 200。登录操作后曾短暂观察到“用户名或密码错误”提示，随后才跳转成功；尚不能判定该提示的来源。本地 Halo 日志未发现 RSA 解密或验证码相关异常。本记录不包含账号、密码、Cookie 或请求体。

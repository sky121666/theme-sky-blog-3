# Halo 2.27 隔离业务验收

> 后续决定：用户明确要求直接在 8090 开发数据验收。8092 代理、Halo 与 MySQL 已停止，数据和历史证据保留。8090 已真实完成下单、人工付款确认、附件交付及订阅权益等流程，见 [8090 业务验收](2026-10-23-Halo-2.27-8090业务验收.md)。下文的“授权阻塞”仅说明当时的隔离副本，不代表当前 8090 状态。

2026-10-23，按用户确认的方案，在独立数据库中验证账号、商城与 PJAX 流程。结论为**部分通过，订单提交及支付受隔离副本的商城授权状态阻断**，不能登记为全流程通过。

## 环境与保护范围

- 原实例：`http://localhost:8090`，Halo Pro `2.27.0`，继续连接原有远端 `skyblog1`；本轮没有重启或调整原实例。
- 测试实例：`http://localhost:8092`，仅绑定本机回环地址，使用同一 Halo 镜像及独立 MySQL 容器、数据目录。
- 测试数据库来自 2026-10-22 已完成恢复验证的升级前备份，由测试 Halo 单独迁移到 2.27；它不是对当前远端数据库的实时镜像。
- 测试 Halo 和 MySQL 位于 Docker 内部网络，没有外部默认路由；本机入口通过独立代理转发。浏览器手机测试也阻断其他来源的请求。
- 主题目录以只读方式挂载。两个实例实测构建均为 **`0.9.49 / bbf7ff411b88`**，源码指纹、manifest 和 Shell 文件字节一致；测试实例安装插件库存为 46 个。
- 测试账号、头像附件、两个商品、两项订阅方案、购物车与结算上下文均只写入隔离副本。原实例查询不到本轮测试账号。

私有运行目录：仓库外本机私有验收目录。该目录含数据库、配置与凭据，仅供本机使用，不进入仓库或安装包。环境保留运行，方便继续验收。

## 订单提交阻塞

会员结算“去支付”返回 HTTP 400，服务端明确提示：

> Halo 商城版授权未激活，无法使用此功能。

独立副本的授权状态为 `unknown / ReportLicenseError`，错误指向 `license.lxware.cn` 的外联校验；原 8090 实例状态仍为 `active`。本轮隔离网络禁止该外联，因此不能把副本的结果归因为主题故障，也不能据此声称原站无法下单。

失败后当前结算内容仍被保留，并出现通用加载失败提示；购物车数据保留。通过后台只读查询确认，隔离库订单数仍为 **0**。未绕过授权检查或改写授权记录。

以下流程尚未验收：订单创建、订单详情与访问保护、支付初始化与失败恢复、支付轮询离开清理、支付终态、取消订单、订阅权益生效与续订、数字资源交付、邮件访问链接。此前合成 fixture 的通过结果继续保留原有范围。

当时评估的后续方案是仅允许副本连接授权服务；用户随后选择直接使用 8090 开发数据，因此没有应用该网络调整，也无需再为副本授权暂停业务验收。

# PJAX 导航重构（2026-09-28）

本轮按已确认的 B → A → C 顺序实施：先收紧离页守卫与提交边界，再统一链接入口，最后迁移页面就绪事件。范围为主题导航及其消费者，保留原有 full / same-variant 执行器与历史协调器。未升级依赖、Halo 或插件，未执行生产部署或推送；实现完成后按用户授权分批本地提交。

下方初始验收对应 `e38fc0f9f22f`；随后 Docsme 目录补验发现并修复标题遮挡，当前工作区构建及其验证见文末“Docsme 补验与修复”。不同构建的验证结果分别保留。

## 实际修改

| 批次 | 修改 | 影响范围 |
| --- | --- | --- |
| B：离页与提交 | 两类草稿先全部投票，响应与资源就绪后统一复核和清理；same → full 回退复用许可；原生恢复使用短期、可撤销许可 | 桌面编辑、前端设置、窗口关闭、错误恢复、前进后退 |
| A：链接入口 | 增加纯链接策略与单一 document 冒泡监听；删除逐链接绑定、动态扫描和小组件导航兜底 | Header、Dock、桌面图标、小组件、Docsme、列表动态内容及缓存恢复链接 |
| C：就绪事件 | 统一 accepted / ready / settled；只有当前导航完成 DOM、资源、组件和历史收尾后发 ready；迁移消费者并配对销毁监听 | 窗口标题栏、菜单、滚动条、桌面、Docsme、Moments、插件增强 |

只新增三个生产模块：`navigation-link-policy.js`、`click-controller.js`、`navigation-admission.js`。删除 `link-attach.js`。页面通过 `a.pjax-link[href]` 声明接管；`attachLink` 只保留添加 class 的兼容行为。

新增模块及核心挂点带 `@theme-navigation-contract v1` 标识，具体入口、事件字段、失败语义和恢复顺序见[主题导航契约](主题导航契约.md)。该标识与插件 `Contract version` 分开管理，不自动提升任何插件的 `testedVersion`。

## 验证中发现并修复

- Pjax 构造时注册的 `popstate` 监听会先于后注册的主题监听运行，导致一次历史操作两次准入；已调整注册顺序，并验证真实前进、后退与否决。
- 重复 title / 窗口根节点的响应可能过早清理源页；改为完整结构检查通过后再提交，四类异常响应均经原生交接回归。
- same-variant 导航到隐藏窗口时，目标已载入但窗口未显示；已补显式恢复显示及真实点击回归。
- 未知 history index 的离页否决会使 Online Monitor 的主题私密标记被目标状态覆盖；已在恢复源历史项前恢复主题维护的标记，并用真实浏览器回归。没有修改插件或 Halo Core。
- Moments 可选缓存写入抛出 `QuotaExceededError` 时，会跳过分页取消。已让缓存失败不阻断取消；真实模板表达式的 Chromium 故障注入先失败、修复后通过，并断言无异常外泄。
- 双端入口矩阵复现移动 Docsme 的工具栏（层级 20）遮挡侧栏（18）的“项目大厅”链接。已将移动侧栏与遮罩调整到 22 / 21，位于工具栏上方；以真实指针点击及遮罩关闭验证，不使用强制点击。

## 2026-09-29：Header 视图连续性与窗口按钮

用户截图暴露了上一轮验收的不足：Header `/links` 与 `/links?view=friends` 虽然走 same-variant PJAX、URL 和最终内容正确，却重新请求 HTML 并重建 Links 组件，造成整窗骨架闪现；侧栏使用现有组件切换，没有这一过程。真实点击复现中 document 未重建、Links root 被替换，新专项首先在 root 保留断言失败。

- Header 仍使用唯一导航点击入口。Links lifecycle 仅为来源、目标均是上述两个简单 URL 的切换提供同步 local 计划，与侧栏共用 `showPrimaryView`。跨应用、复杂参数、hash、详情 / 申请表继续走原有流程；没有新增 Header 监听器或另一套路由。
- local 切换保留组件、插件实例、搜索状态，提交 URL / 标题 / 历史并在 Alpine 更新后发 ready；同 URL 不增加历史，前进后退不重新请求 HTML。原离页守卫、许可复核及旧请求抢占继续有效。
- 桌面小组件和 LightGallery 的 ready 订阅跳过 local，避免无关重绘。应用元数据读取失败时保留已提交视图，以当前 DOM 标题更新缓存。详细边界见[主题导航契约](主题导航契约.md#应用内视图切换)。
- 通用窗口按钮改为 20px 宽点击区域、12px 圆点，圆点中心距 20px、视觉边缘间距 8px；移除模板的额外 gap 及 Links 单独宽度覆盖。插件布局标题栏、豆瓣手机标题栏统一为 12px + 8px。登录片段和主题设置原本已是这一尺寸，保留原样；代码块装饰不属于窗口控件。

## 2026-09-29：内页直达的背景桌面数据

用户随后发现直达 `/links` 等内页时，背景最新文章和朋友圈一直停留在骨架。已复现：服务端有意只在首页查询已配置组件的 Finder 数据，内页协议 `sources.hydrated=false`；客户端此前只有打开通知中心或 PJAX 返回首页时补数，背景桌面缺少加载入口。打开通知中心后同一页面立即补齐，证明不是延迟加载 renderer 本身的问题。新直达测试在修改前等待补数超时。

修复沿用原数据协议，保留所有 SSR 查询门禁：

- 新增 `runtime/widgets/data-loader.js`，由桌面和通知中心共用一次首页数据请求，只提取惰性 JSON 协议，不执行响应脚本、不改变当前 URL。
- 桌面初始化完成、视口或组件开关变化后，按需补齐内容组件数据；系统组件、空布局、禁用、移动端隐藏、通知中心专属组件不触发背景请求。通知中心仍在打开时按需加载。
- 同一个文档共用请求，调用者独立取消；全部取消时才中断底层请求。12 秒超时覆盖响应正文，错误不会永久显示骨架，可手动重试。较晚的后台响应不能覆盖 PJAX 已安装的数据。
- `applyHomeWidgetProtocol` 只更新内容来源和相关渲染缓存，保留窗口、组件位置、图标及未保存布局。组件销毁后不继续更新其状态。

## 2026-09-29：瞬间详情顶部返回列表

详情标题栏虽然声明 `href="/moments"`，原有内联事件却在浏览器有历史记录时优先调用 `history.back()`。直接访问详情可能退到站外或新标签页，从其他页面进入也不能保证返回瞬间列表。

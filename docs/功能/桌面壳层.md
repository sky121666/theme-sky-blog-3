## 结论

桌面壳层是当前主题的公共运行底座。
它负责：

- 顶栏
- Dock
- 桌面图标
- 桌面小组件
- 主窗口
- Swup 无刷新导航与 PJAX 兼容接口

如果一个改动会影响多个页面，优先看这里。

## 当前职责边界

### 壳层负责

- shell HTML 结构
- 全局主题状态
- PJAX 内容替换
- 桌面层交互
- 浏览器窗口的统一行为

### 壳层不负责

- feature 页面正文细节
- 图库内容布局
- 瞬间内容布局
- explorer/reader 正文样式

这些都应该归对应 feature 目录。

## Swup 与窗口导航

站内导航由共享 Swup 实例执行，`window.pjax` 和旧事件名保留为兼容入口。应用继续通过主题统一入口取得离页许可，不能直接建立第二套导航。

导航更新：

- `#window-frame-root` 内部内容

不替换：

- Header
- Dock
- Desktop Surface
- 主窗口壳层外框

当前相关实现：

- [/src/shell/desktop-shell/runtime/desktop/pjax/index.js](../../src/shell/desktop-shell/runtime/desktop/pjax/index.js)
- [/src/shell/desktop-shell/runtime/desktop/pjax/swup-navigation.js](../../src/shell/desktop-shell/runtime/desktop/pjax/swup-navigation.js)
- [/src/shell/desktop-shell/runtime/desktop/pjax/css-router.js](../../src/shell/desktop-shell/runtime/desktop/pjax/css-router.js)
- [/src/shell/desktop-shell/runtime/desktop/pjax/protocol.js](../../src/shell/desktop-shell/runtime/desktop/pjax/protocol.js)

从桌面打开支持的公开应用时，先反馈窗口位置和外观，再接入内容；窗口内换页继续显示原内容。公开链接按悬停、聚焦或触摸意图预取；可复用结果由服务端缓存规则决定。登录、下载、客户中心等入口保持各自导航边界，详见[主题导航契约](../主题导航契约.md)。

## 搜索、通知与 Dock

- 顶栏按钮或 `Cmd+K` 打开搜索，本站结果进入统一无刷新导航；Enter 打开结果后弹窗关闭，桌面和 Dock 保留。外站结果按插件原生方式打开。
- 顶栏时间打开通知中心。面板首次展开保持布局尺寸稳定，窄屏内容在面板内滚动；关闭与读屏分组名称沿用当前操作状态。
- Dock 的图片、图标和文字回退沿用菜单配置；文字图标按统一中心对齐。本地开发站改用普通图标属于站点配置，不会替换其他站点的菜单。

## 首屏加载与交互就绪

前端「系统设置 → 首屏加载」默认选「普通显示」；可改为「开机启动」并设置频率、标识，再点击「应用」。开机层在完整访问时由 SSR 片段尽早建立，不在 PJAX 换页时重播。普通显示会先呈现首屏投影，壳层和桌面内容在原位置补齐。正式开机时，黑色背景上只显示标识和细进度条。等待第一个就绪信号时，亮段轻轻移动；收到信号后按此场景实际完成的阶段推进。桌面等待壳层和桌面内容，应用页等待壳层和应用，登录页等待认证表单。就绪即淡出，超时最多 2 秒，超时不会把进度先补满。

直接访问文章或文档正文时优先显示可阅读内容，不播放遮挡正文的开机层；首页等其他入口继续按设置的频率执行。

点按背景或按 Esc 可立即退出；按 Tab 或 Shift+Tab 才显示并聚焦「跳过」，按 Enter 或空格确认。这次点按不会激活被遮住的桌面控件。设置预览另有常显的轻量文字「结束演示」；只点击背景不会打断预览。

「演示一次」只预览系统设置的当前草稿；取消设置或关闭未保存窗口会放弃草稿，不影响已发布配置。播放记录保存在标签页会话中；历史恢复、主题自动恢复重载和 PJAX 不当作新的首次访问。减少动态效果时跳过开机层。启动层不能改变站点登录与权限规则。实现入口见 [/src/shared/startup-controller.js](../../src/shared/startup-controller.js) 和 [/templates/assets/build-startup.html](../../templates/assets/build-startup.html)，操作说明见 [前端系统设置](../设置/前端系统设置.md#首屏加载)。

## 什么时候改这里

适合改壳层的需求：

1. 顶栏按钮行为

## 我想配什么，先配哪里

这些需求优先去后台设置，不要先改代码：

1. 顶栏 / Dock 菜单来源：看 `navigation.header.menu_name` 和 `navigation.dock.menu_name`
2. 顶栏标题和图标：看 `header.logo.*`
3. Dock 外观和交互参数：看 `dock.*`
4. 开发日志开关：看 `developer.debug_mode`

## 菜单位置兼容规则

Halo 后台菜单是一棵通用导航树，主题不会把它自动改造成不同位置的专用字段。不同位置只按自己的能力消费同一份菜单数据。

| 位置 | 配置入口 | 支持层级 | 消费规则 |
| --- | --- | --- | --- |
| 顶栏桌面端 | `navigation.header.menu_name` | 一级 + 二级 | 一级显示为顶栏文本；有二级菜单的一级项作为分组入口，不直接跳转。 |
| 顶栏移动端 | `navigation.header.menu_name` | 一级 + 二级 | 无二级的菜单项直接显示；有二级的菜单项按分组展开。 |
| Dock | `navigation.dock.menu_name` | 一级 | 只把一级菜单项渲染为 Dock 图标；二级菜单不会展开。 |
| 页面侧边栏 | 页面业务数据 | 由页面决定 | 通常来自分类、标签、相册、友链分组、Docsme 目录等，不等同于全局菜单。 |
| Footer | `<halo:footer />` | 非菜单体系 | 由 Halo 或插件注入，不从主题菜单设置读取。 |

兼容说明：旧版本保存过的 `header.source.menu_name` 和 `dock.source.menu_name` 仍会被模板读取；在「菜单」设置页选择新值后，以 `navigation.header.menu_name` / `navigation.dock.menu_name` 为准。模板也兼容过渡期的 `navigation.source.*`。

建议：

- Header 使用结构完整的主导航菜单。
- Dock 单独准备扁平快捷入口菜单。
- 如果一个菜单项既有链接又有子菜单，Header 会优先把它当作分组标题。
- 菜单项元数据中的图标主要服务 Dock，也会用于 Header 二级菜单；顶层 Header 文本菜单不显示图标。

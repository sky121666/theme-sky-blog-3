## 实测发现后的追加修复

- 冷资源专项发现：已缓存目标 CSS 必须在原始 `loadUrl` / `pjax:send` 之前同步激活；此前异步资源流程会晚一个 microtask。现已补同步 staging，仅允许 origin/path/v/r 全部一致的完整缓存资源，保留旧页 CSS 直到导航接管。离线反例同时拒绝缺少身份、错误构建和错误节点；真实 warm CSS 断言保持不变并通过。后续专项暴露旧测试要求只发送最后一个 HTML 请求，与并行准备约定冲突：保留首次失败记录后，新增对真实旧 XHR 的 `abort`、完成事件、`pushState`、资源释放后完整 DOM/history 不变的观测；两种竞争都证明仅最新页面提交一次。修正后的 8 项完整通过，没有通过放宽超时或忽略响应错误解决。
- Docsme 小组件：`totalDocs` 仅统计 DOC，不包含 TREE，不能用 0 禁用合法目录项目。只在缺失 permalink 时禁用；小尺寸默认优先有文档项目，显式选择仍被保留。覆盖三尺寸、0 文档/缺链接/普通/预览及默认/指定选择共 14 个行为场景。
- Docsme 样本发现：仅去除测试参数 `_docsme_verify`，保留语言/版本查询；同源去重后有界遍历全部已发现候选，保存截断和跳过原因。中间构建 `3109fe1e01c8` 发现 23 个唯一路由、检查 20/20 个正文候选；真实代码与 Mermaid 通过，KaTeX 样本仍未观察到。`/docs/123` 404 继续使专项退出 1。最终构建结果另列，未沿用旧报告。
- Docsme 报告可靠性：候选 `b43d32430c08` 首次扫描因 20 秒导航超时而提前退出，原脚本未更新报告，批处理曾复制旧 `3109fe1e01c8` 文件。该副本已标记无效并排除归档。现于开始时写当前运行身份，在 `finally` 保存进度、失败与结束状态；批处理拒绝过期时间或不同构建的文件。导航仍为 20 秒上限，追加最多 2 秒被动诊断；独立候选可继续检查，原失败仍使命令失败。离线反例覆盖报告残留、诊断超时、headers 后正文 pending 和浏览器失效。

## Docsme 富内容生命周期收口

中间构建 `17973dba79a1` 的图表异常继续核查后，确认主题的成功判定也有缺陷：错误 SVG 或 `run()` 拒绝后的残留 SVG 会被当成成功。现已逐图等待执行，拒绝及官方错误 SVG 标记不再计为成功；保留源内容和明确回退状态，不能只以 SVG 数量验收。

对照安装的 Docsme `1.10.0` JAR 中完整 `modules/plugin-scripts.html` 后，在主题 `templates/modules/docsme-app/content.html` 使用局部资源片段保留 DOC 的 KaTeX CSS，在 `src/apps/docsme/runtime.js` 保留 project/version/language 搜索筛选语义，由同一生命周期控制富内容 JS 的去重加载与初始化。没有复制插件整个模板或改动 JAR。

- 渲染前等待容器可测量，最多 2 秒；导航/销毁会取消等待，清除计时器，旧任务不再提交完成状态。
- 主题切换及 PJAX 继续串行、逐图处理；错误图和有效图分别归属，加载中的相同 URL 脚本只复用一次。
- 主题自有脚本失败可清理并重新加载，外部已有脚本不删除；请求超时不会被当成成功。
- 13 项离线反例覆盖错误/残留 SVG、混合多图、显示等待、截止时间、取消、重复绑定/解绑和加载资源复用，已接入现有 discovery 检查链。
- 当前主题没有 `#btn-search` 实例；搜索过滤绑定仅通过受控宿主验证，不将它称为真实项目搜索入口验收。

此前插件 DCL 初始化与初始隐藏窗口没有同步，存在时序缺口；本次没有错误瞬间的尺寸记录，不能倒推所有几何异常必然由该缺口引起。新构建的真实图表结果以最终运行表为准。

## 首屏布局位移复核

中间构建 `3109fe1e01c8` 的 10 页无交互采样虽未观察到 JavaScript 异常，多个内容页的 CLS 为约 `0.9754`。旧审计命令只检查运行时异常，退出 0 不代表性能合格，因此保留该报告并继续修复。

Ego 的 `layout-shift` 和样式时间线定位到：bootstrap 将已应用 CSS link 的 `r=Halo metadata` 直接替换成 manifest revision，下载替换样式期间 BODY 短暂变为浏览器默认 margin 8px，尺寸从 1440×960 变到 1424×3280.5，再恢复。单次 BODY 位移约 `0.970833`，不是指标累加误差。

已实施保留 SSR 样式直到目标身份的替换样式加载成功，然后保持原顺序交接；失败和超时保留原样式、清理失败节点并报告错误，不能以隐藏页面或忽略位移来降低分数。审计新增单页实验室 CLS ≤ 0.1 的回归门槛，缺测不记作通过；依据 [CLS 官方定义与建议](https://web.dev/articles/cls)，但此单次实验室窗口不代表真实用户第 75 百分位或完整访问周期达标。

上一候选 `b43d32430c08` 首轮 10 页均通过，CLS `0.0045–0.0057`，LCP `492–1224ms`。随后改进门槛比较精度（不先四舍五入，拒绝首帧前已隐藏的样本），定向 12 项指标测试通过；同一构建复测 9 页通过，原始 CLS `0.0044786–0.0056203`，另 1 页因 AI 插件模块请求 pending 导致 `DOMContentLoaded` 超时、指标缺测，整轮退出 1。两次结果都保留，不能以第一次通过覆盖最新失败。两轮均无交互样本，INP 为 null。

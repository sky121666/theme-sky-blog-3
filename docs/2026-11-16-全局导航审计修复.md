共享的请求截止工具只负责传输与正文消费，不负责业务 DOM 提交、缓存、重试或全局取消；组件继续持有代次与提交权。写请求超时表示结果可能未知，通过既有权威状态回读核实，不自动重发 POST。

Windows 认证滚动条静态疑点另作隔离命中验证，确认为内部缺陷才补最小修复。多次 DOMParser、未测图片成本等观察不作为本批重构理由。

## 验证顺序

1. 对已确认反例先建立失败回归，再最小修复并验证通过；记录真实顺序，保留审计原证据。
2. 定向验证各 owner、共享预取、Docsme、历史/草稿、商城和小组件；独立复核本批修改。
3. `pnpm run check` 先重建，再检查类型/契约/构建结果；修复本批回归，不降低既有门槛。
4. `pnpm run verify:reload`，然后在 8090 验证受影响页面与共享 Shell；按项目要求执行 `SMOKE_BASE_URL=http://localhost:8090 pnpm run smoke:playwright`。外站 favicon 等与本批无关失败单独记录，不伪称命令全通过。
